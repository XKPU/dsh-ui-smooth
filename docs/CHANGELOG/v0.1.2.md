# Changelog

## [v0.1.2] - 2026-11-28

### Fixed

- **后台保活的音频流真正算作在播放**：此前 40 Hz 振荡器的增益是 0.0001，低于 Chromium 判定「可听」的 -72.25 dBFS 门槛，渲染进程仍会被后台节流。现在增益改为 0.002（约 -63 dBFS 的正弦），高于该门槛但远低于扬声器可再现的水平，因此能稳定豁免后台节流；「后台节流」开关打开时音频流仍随之关闭。
- **音频上下文被挂起后自动恢复**：AudioContext 可能在任意时刻转为 `suspended`，原先只在首次手势与切回前台时尝试 `resume()`。现在每 15 秒再检查并重试一次恢复；一旦回到 `running`，即移除手势与可见性监听。关闭保活时一并清理恢复定时器与探针定时器。

### Added

- **节流探针**：`throttle()` 的返回值新增 `gap` 字段——500 ms 探针计时器实测到的最长间隔（毫秒）。持续接近 500 表示页面没有被节流；被节流时会明显变大，可用于诊断音频流是否真的生效。
